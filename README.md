Noyo operates benefits data infrastructure that automates the exchange of employee benefits enrollment data between benefits administration platforms, brokers, and insurance carriers. Its APIs let ben-admin platforms connect a group to a carrier, send member snapshots (new hires, qualifying life events, open enrollment, COBRA, terminations), and receive near-real-time, field-level tracking of every change through to carrier confirmation. The Fulfillment API manages groups, connections, employees, dependents, enrollments, plans, renewals and member requests; the Tracking API surfaces differences and discrepancies; the Carrier API exposes carrier network configuration. Noyo standardizes the messy, EDI-heavy world of carrier data exchange behind a modern REST interface with webhooks and a sandbox.

**Areas:** Company · Healthcare · Insurance · Employee Benefits · Enrollment · Benefits Administration · Insurance Carriers · Data Exchange · Webhook · Health Insurance

## How this profile is made

API Evangelist profiles a company's public API surface the way a developer would find it: the website, developer portal and documentation, the specifications it publishes, its public repositories, and its pricing, status and changelog pages. From that it derives the properties above — contracts split per API, workflows, schemas, collections, governance rules, plans and rate limits — and scores them against the published [Kin Score rubric](https://github.com/api-evangelist/kin-score).

The artifacts are published on [APIs.io](https://apis.io), not in this repository. This repository is the public record for Noyo: the place to say something is wrong, missing or out of date, and to ask for a re-score or a removal.
